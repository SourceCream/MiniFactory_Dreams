# Mini Factory Dreams

Небольшая idle-игра для Android, выполненная как тестовое задание на Unity. Три производственные машины автоматически приносят монеты; игрок открывает и улучшает их, использует временное ускорение и получает доход за время отсутствия.

Примерное фактическое время работы: **5 часов 10 минут**. Android-сборка проверялась на **Samsung Galaxy S10, Android 12**.

## Запуск в Unity

1. Установить **Unity 6000.3.22f1** через Unity Hub. Для Android нужны модули Android Build Support, Android SDK & NDK Tools и OpenJDK.
2. Клонировать репозиторий, добавить его корневую папку в Unity Hub и открыть проект. Дождаться импорта ресурсов и установки пакетов.
3. Открыть сцену [MainScene](Assets/_Project/Scenes/MainScene.unity).
4. Нажать **Play**. Для проверки интерфейса выбрать портретное разрешение Game View.

Первый пресс открыт сразу. Кнопки на карточках показывают стоимость и прирост производства. Заблокированные машины затемнены и не приносят доход. Меню «Магазин» содержит один набор из 1000 монет. По умолчанию работает Unity IAP Fake Store: реальные деньги не списываются, товар в Google Play создавать не требуется.

Аналитика включается автоматически. В Unity Console нужно включить обычные сообщения Log и поставить фильтр `[Analytics]`. При запуске появляется `game_started`, при игровых действиях появляются остальные события. Если редактор ещё использует старые скрипты, остановить Play Mode, выполнить **Assets / Refresh**, дождаться компиляции и запустить игру заново.

## Сборка Android

1. Открыть **File / Build Profiles**, выбрать существующий профиль Android в `Assets/Settings/Build Profiles` и сделать его активным.
2. Проверить список сцен: включена `Assets/_Project/Scenes/MainScene.unity`. Профиль использует общий список сцен проекта.
3. Текущие параметры Player Settings: портретная ориентация, **IL2CPP**, **ARM64**, минимальный API **25**, Target API выбирается автоматически из установленного SDK.
4. Для запуска на телефоне включить USB debugging, подключить устройство и подтвердить разрешение отладки на его экране. Выбрать телефон в Run Device.
5. Нажать **Build And Run** и сохранить APK, например, в `Builds/minifactory.apk`. Для сборки без установки использовать **Build**.

Первый Android build может занять заметно больше времени из-за подготовки Gradle, IL2CPP и кэшей. Папки сборок, APK, Library и временные файлы исключены из Git.

## Системы и архитектура

Исходники находятся в `Assets/_Project/Scripts`. Модули разделены assembly definition-файлами; сторонний DI framework не используется.

| Модуль | Ответственность |
| --- | --- |
| `Economy` | Чистый C#: баланс, машины, цены, производство, интервал буста и учёт прошедшего времени. Не зависит от Unity. |
| `Configuration` | ScriptableObject-конфиги и преобразование настроек в неизменяемые определения для игровых систем. |
| `Persistence` | Версионированный JSON, запись через временный файл и восстановление из резервной копии. |
| `Shop` | Выдача награды, защита от повторного начисления и состояния покупки через интерфейс `IStoreGateway`. Не зависит от Unity IAP. |
| `Purchasing` | Адаптер `UnityIapGateway`: подключение SDK, получение товара, покупка и подтверждение заказа. |
| `Analytics` | События и интерфейс провайдера, одновременная отправка нескольким провайдерам, изоляция их ошибок. Не зависит от Unity. |
| `Presentation` | uGUI, карточки машин, окна магазина и офлайн-дохода, анимации, safe area и Console/Debug provider. `FactoryScreen` создаёт и связывает системы. |

Графика интерфейса и машин построена из uGUI-элементов и процедурной геометрии `FactoryGraphic`. Анимация работающих машин зависит от их состояния и множителя производства.

Игровые настройки отделены от прогресса. Для будущего Remote Config можно подготавливать те же определения машин, буста и товара из удалённых значений и менять источник данных в точке сборки систем. Сама логика экономики от способа загрузки настроек не зависит. Удалённый провайдер сейчас не подключён.

## Конфигурация и прогресс

| Конфиг | Содержимое и значения по умолчанию |
| --- | --- |
| [EconomyConfig](Assets/_Project/Configs/EconomyConfig.asset) | Начальный баланс 0, три машины, цены и производительность, максимум офлайн-дохода 28 800 секунд, то есть 8 часов. |
| [BoostConfig](Assets/_Project/Configs/BoostConfig.asset) | Ускорение включено, длится 60 секунд, множитель производства 2. |
| [ShopConfig](Assets/_Project/Configs/ShopConfig.asset) | Consumable `coins_pack_small`, награда 1000 монет, Fake Store включён. Цена поступает из магазина. |

Изменять параметры можно в Inspector до запуска игры. Первая машина в списке начинает с уровня 1, остальные с уровня 0. Производительность машины равна базовой производительности, умноженной на уровень. Стоимость улучшения: `ceil(baseUpgradeCost * upgradeCostMultiplier^(level - 1))`. Стабильные ID связывают машины с сохранённым прогрессом.

Сохранение `factory-save.json` находится в `Application.persistentDataPath`. В Windows Editor это обычно `%USERPROFILE%/AppData/LocalLow/SourceCream/MiniFactory_Dreams`. Рядом хранится резервная копия `.bak`. Текущая версия формата 4, поддерживается загрузка версий 1-4. Сохраняются баланс, уровни, временные границы буста, учтённое UTC-время и идентификаторы выданных покупок.

Прогресс сохраняется после игровых покупок и активации буста, каждые 5 секунд активной игры, при уходе в фон и завершении. События паузы и потери фокуса объединяются, чтобы одна пауза не давала повторного начисления. При возвращении учитывается длительность отсутствия, лимит офлайн-дохода и пересечение с бустом. Окно показывает время отсутствия и уже начисленную сумму.

Для проверки с нуля нужно остановить игру и убрать `factory-save.json`, `.bak` и `.tmp` из её каталога сохранений. Это удаляет локальный прогресс и историю выданных покупок.

## Аналитика

Активен `DebugAnalyticsProvider`, который пишет события в лог с префиксом `[Analytics]`. Для добавления другого провайдера нужно реализовать `IAnalyticsProvider` и включить его в список при создании `AnalyticsService`. Существующий Debug provider можно оставить подключённым одновременно.

| Событие | Основные параметры |
| --- | --- |
| `game_started` | Наличие загруженного сохранения, баланс, количество машин, платформа, версия приложения. |
| `machine_unlocked` | ID машины, уровень, стоимость, производительность, оставшийся баланс. |
| `machine_upgraded` | ID машины, новый уровень, стоимость, производительность, оставшийся баланс. |
| `boost_started` | Длительность, множитель, время окончания в UTC. |
| `boost_finished` | Длительность, множитель, признак завершения во время отсутствия. |
| `offline_income_applied` | Время отсутствия, учтённое время, монеты, применение лимита, баланс. |
| `purchase_succeeded` | ID товара и транзакции, начисленные монеты, баланс. |
| `purchase_failed` | ID товара, причина, этап ошибки и ID транзакции, если доступен. |

Успех покупки фиксируется после сохранения награды. Повторная доставка уже сохранённой транзакции не создаёт нового события успеха. Ожидание оплаты не считается неуспешной покупкой. Ошибка подтверждения может прийти после выдачи награды; для её различения используется параметр `stage=confirmation`.

## Проверки

Тесты находятся в [Assets/_Project/Tests/EditMode](Assets/_Project/Tests/EditMode). В Unity открыть **Window / General / Test Runner**, выбрать **EditMode** и нажать **Run All**.

Последний автоматизированный прогон от 13.10.2026: **126 пройдено, 0 ошибок**. Проверяются экономика, сохранения и их восстановление, офлайн-доход, буст, покупки, аналитика и взаимодействие моделей с интерфейсом. Прогон выполнялся в отдельной копии проекта с изолированным каталогом сохранений.

Дополнительно во время разработки выполнялись проверки в Play Mode: производство, нажатия UI, восстановление прогресса и покупки через Unity IAP Fake Store. В репозитории сохранены Edit Mode тесты; временные скрипты этих дополнительных проверок в него не включены.

Android-сборка проверялась на Samsung Galaxy S10 с Android 12, включая экономику, интерфейс, сохранения, офлайн-доход и буст. Магазин дополнительно проверен в Editor через Fake Store. Отдельный полный прогон Android-сборки после добавления аналитики не зафиксирован. Замеры FPS, памяти и времени кадра на устройстве не проводились.

## Ограничения и следующие шаги

- IAP работает в тестовом режиме. Реальные транзакции Google Play, проверка чеков на сервере и восстановление оплаченного баланса после удаления данных приложения не реализованы.
- В обработке IAP остаются два недочёта: кнопка покупки становится доступной при отложенной оплате и до получения асинхронного ответа о подтверждении предыдущего заказа. Это нужно исправить и проверить перед подключением реальных платежей.
- Сохранение локальное. Учёт времени защищает от повторного начисления при переводе часов назад, но не от манипуляций временем вперёд. Серверное время и облачное сохранение не используются.
- Аналитика выводится только в лог, без очереди, удалённой доставки и гарантии сохранения событий при аварийном завершении. Firebase Remote Config, внешний Analytics provider и профилирование остались за рамками выполненной работы.
- Android Application Identifier пока оставлен от шаблона: `com.DefaultCompany.urp_2d`. Публикация в магазине и релизная подпись не настраивались.

Следующий шаг: повторная проверка финальной сборки на устройстве, доработка состояний IAP и базовое профилирование. Затем можно подключать удалённую конфигурацию и внешний провайдер аналитики.

Разработка велась через `develop` и отдельные feature-ветки, с Conventional Commits и Pull Request. Финальное состояние для сдачи должно быть слито в `main`. Использование ИИ описано в [AI_USAGE.md](AI_USAGE.md). Лицензия проекта: [MIT](LICENSE).
